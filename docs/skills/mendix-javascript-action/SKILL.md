# Mendix 10.24 JavaScript actions

A JavaScript action is client-side code that a **nanoflow** calls. It runs in the browser (web) or in the native
app. Studio Pro generates `javascriptsource/<module>/actions/<Name>.js`. You write code only in the kept regions.

Target: Mendix Studio Pro **10.24.13** (React client and Dojo client), Client API `mx-api` (10.20+).

## 1. What you must know (summary table)

| Topic | Rule for 10.24.13 | Why it matters |
|---|---|---|
| File | `javascriptsource/<module lower-case>/actions/<Name>.js`, `export async function <Name>(…)` | Regenerated on save/deploy |
| Kept regions | Import list (top), `// BEGIN EXTRA CODE`…`// END EXTRA CODE`, `// BEGIN USER CODE`…`// END USER CODE` | Code anywhere else is lost |
| Where it runs | Only in nanoflows (JavaScript action call). Not in microflows | Server logic belongs in a microflow/Java action |
| Async | Return a value or a `Promise`; the nanoflow waits for it. Use `async`/`await` | Unhandled rejection = nanoflow error |
| Object parameter | `MxObject` | Use `get`, `set`, `getGuid`, `getEntity`, `isA` |
| List parameter | `MxObject[]` (may be empty) | |
| Decimal, Integer/Long | `Big` (big.js), not `number` | `new Big(…)`, `.plus()`, `Number(big)` |
| DateTime | JavaScript `Date` | |
| Enumeration | `string` = the enum **key** | |
| Entity type parameter | `string` = entity name, e.g. `"Sales.Order"` | Use with `create({ entity })` |
| Nanoflow parameter | async function: `await OnCreated({ Order: order })` → nanoflow return value | Keys = nanoflow parameter names |
| Microflow parameter | async function (Studio Pro 10.21+): `await Validate({ Order: order })` | Runtime operation; strict-mode compliant |
| Optional parameter | Value is `undefined` when not given | Check before use |
| Create object | `import { create } from "mx-api/data"` → `await create({ entity: "Sales.Order" })` (10.23+) | `mx.data.create` is legacy |
| Set attribute | `obj.set("Number", "A1")`; Decimal: `obj.set("Total", new Big("12.50"))` | Attribute name without module |
| Reference (1-*) | Owner side: `order.set("Sales.Order_Customer", customer.getGuid())` or `order.addReference(…)` | Qualified association name + **GUID string** |
| Reference set (*-*) | `order.addReferences("Sales.Order_Tag", guids)`, `order.removeReferences("Sales.Order_Tag", guids)`, `order.set("Sales.Order_Tag", guids)` (replace) | Takes an array of GUID strings |
| Read association | `order.getReference("Sales.Order_Customer")` → GUID; `order.getReferences("Sales.Order_Tag")` → GUID[] | Returns ids, not objects |
| Commit | Prefer a **Commit** activity in the nanoflow after the action. In code: `import { commit } from "mx-api/data"` | `create`/`commit`/`remove` from the Client API are restricted when strict mode is on |
| Retrieve | Prefer a **Retrieve** activity in the nanoflow and pass the list in. In code: `retrieveByEntity` from `mx-api/data` | XPath retrieves are not available offline |
| Return type | Every type a parameter can have; Boolean must be `true`/`false`, never `undefined` | `undefined` Boolean breaks the nanoflow |
| Platform | All (default) / Web / Native | Native-only APIs force a native nanoflow |
| Expose | **Expose as nanoflow action** (caption + category) puts it in the Toolbox | |
| Legacy | `mx.data.*`, `mx.ui.*` (global `mx`) still work in 10 but are deprecated in 11 | New code: `mx-api/*` modules |

## 2. Define the action

In Studio Pro: **App Explorer > module > Add other > JavaScript action**. Set parameters (Object, List, Entity,
Nanoflow, Microflow, Boolean, Date and time, Decimal, Enumeration, Integer/Long, String), the return type, the
platform, and optionally **Expose as nanoflow action**. Saving generates the `.js` file.

With dump-it:

```json
{ "ops": [ { "op": "createJavaScriptAction", "module": "Sales", "name": "JS_CreateOrder",
  "parameters": [
    { "name": "Customer", "type": "Sales.Customer" },
    { "name": "Tags", "type": "List(Sales.Tag)" },
    { "name": "Total", "type": "Decimal" },
    { "name": "OnCreated", "type": "Nanoflow" } ],
  "returns": "Sales.Order",
  "platform": "Web",
  "exposed": { "caption": "Create order", "category": "Sales" } } ] }
```

Notes:
- Add imports (for example `import { create, commit } from "mx-api/data";`) below the generated imports.
  They are kept.
- Helper functions go in EXTRA CODE or inside the function body.
- Parameter names in the function are the names from the action definition.

## 4. MxObject API you need

| Call | Returns | Use |
|---|---|---|
| `obj.get("Attr")` | value: string, `Big` (numbers), boolean, `Date`, enum key | Read an attribute |
| `obj.set("Attr", value)` | – | Change an attribute (client only until commit) |
| `obj.getGuid()` | string | Id for references and API calls |
| `obj.getEntity()` | `"Sales.Order"` | Entity name |
| `obj.isA("Sales.Order")` / `obj.inheritsFrom(...)` | boolean | Type check |
| `obj.has("Attr")`, `obj.isNumeric("Attr")` | boolean | Validate generic input |
| `obj.getAttributes()` | string[] | Attribute names |
| `obj.getReference("Mod.Assoc")` | GUID string or `""` | Read a reference |
| `obj.getReferences("Mod.Assoc")` | GUID[] | Read a reference set |
| `obj.addReference("Mod.Assoc", guid)` | boolean | Reference: set; reference set: add one |
| `obj.addReferences("Mod.Assoc", guids)` | boolean | Reference set: add many |
| `obj.removeReferences("Mod.Assoc", guids)` | boolean | Reference set: remove |
| `obj.set("Mod.Assoc", guid or guids)` | – | Replace a reference / reference set |

Changes on an `MxObject` stay in the client until a commit (nanoflow **Commit** activity or `commit`).

## 5. Recipes

### 5.1 Create an object, set attributes and a reference

```javascript
import { create } from "mx-api/data";
// …
	// BEGIN USER CODE
	if (!Customer) throw new Error("Customer is required");
	const order = await create({ entity: "Sales.Order" });
	order.set("Number", "WEB-" + Date.now());
	order.set("Total", Total ? Total : new Big(0));
	order.set("Status", "Open");                                  // enum key
	order.set("Sales.Order_Customer", Customer.getGuid());       // reference, owner = Order
	return order;                                                 // commit it in the nanoflow
	// END USER CODE
```

Generic entity (Entity parameter `ResultEntity` filling type parameter `T`):

```javascript
const obj = await create({ entity: ResultEntity });
```

### 5.2 Reference set: add, remove, replace

```javascript
const tagGuids = (Tags || []).map(t => t.getGuid());
order.addReferences("Sales.Order_Tag", tagGuids);               // add
order.removeReferences("Sales.Order_Tag", [oldTag.getGuid()]);  // remove
order.set("Sales.Order_Tag", tagGuids);                         // replace all
```

### 5.3 Commit in code (only when the nanoflow cannot do it)

```javascript
import { commit } from "mx-api/data";
// …
await commit({ objects: [order] });
```

The usual pattern is simpler and works with strict mode: return the object and add a **Commit** activity after the
JavaScript action call in the nanoflow.

### 5.4 Call a nanoflow or a microflow passed as a parameter

```javascript
// Nanoflow parameter OnCreated: nanoflow with parameter "Order", returns Boolean
const ok = await OnCreated({ Order: order });

// Microflow parameter Validate (Studio Pro 10.21+): microflow with parameter "Order", returns Boolean
const valid = await Validate({ Order: order });
if (!valid) throw new Error("Order is not valid");
```

The keys are the parameter names of that nanoflow/microflow. The await returns the flow's return value.
You cannot call a nanoflow by name. Pass it as a Nanoflow parameter.

### 5.5 Decimals and dates

```javascript
const total = (Tags || []).reduce((sum, t) => sum.plus(t.get("Price") || 0), new Big(0));
order.set("Total", total);
const asNumber = Number(total);          // only when precision does not matter
order.set("DueDate", new Date(Date.now() + 7 * 24 * 3600 * 1000));
```

### 5.6 Validate input

```javascript
if (Customer === undefined || Customer === null) throw new Error("The Customer parameter is required");
if (!Customer.isA("Sales.Customer")) throw new Error("Customer must be a Sales.Customer");
if (OrderNumber !== undefined && OrderNumber.trim() === "") throw new Error("OrderNumber can not be empty");
```

### 5.7 Fetch data from a REST API and create objects

```javascript
import { create } from "mx-api/data";
// …
	// BEGIN USER CODE
	const response = await fetch("https://api.example.com/orders?customer=" + encodeURIComponent(Customer.get("Name")));
	if (!response.ok) throw new Error("Request failed: " + response.status);
	const rows = await response.json();
	return Promise.all(rows.map(async row => {
		const o = await create({ entity: "Sales.Order" });
		o.set("Number", String(row.number));
		o.set("Total", new Big(row.total));
		o.set("Sales.Order_Customer", Customer.getGuid());
		return o;
	}));
	// END USER CODE
```

## 6. Call the JavaScript action from a nanoflow

Studio Pro: drag **JavaScript action call** (or the exposed action from the Toolbox) into a nanoflow, map the
parameters, set the output variable, then add **Commit** for created/changed objects.

dump-it step (inside `createNanoflow` / `addActions`):

```json
{ "action": "callJavaScript", "jsAction": "Sales.JS_CreateOrder", "variable": "NewOrder",
  "args": { "Customer": "$Customer", "Tags": "$Tags", "Total": "$Total", "OnCreated": "Sales.NF_Order_AfterCreate" } }
```

## 7. Few-shot examples (request → code)

### Example A - "Create an order for the customer, add the selected tags, return it"

Action: `Sales.JS_CreateOrder(Customer: Sales.Customer, Tags: List(Sales.Tag), Total: Decimal) → Sales.Order`.
The nanoflow commits the result.

```javascript
import "mx-global";
import { Big } from "big.js";
import { create } from "mx-api/data";

// BEGIN EXTRA CODE
// END EXTRA CODE

/**
 * @param {MxObject} Customer
 * @param {MxObject[]} Tags
 * @param {Big} Total
 * @returns {Promise.<MxObject>}
 */
export async function JS_CreateOrder(Customer, Tags, Total) {
	// BEGIN USER CODE
	if (!Customer) throw new Error("Customer is required");
	const order = await create({ entity: "Sales.Order" });
	order.set("Total", Total || new Big(0));
	order.set("Status", "Open");
	order.set("Sales.Order_Customer", Customer.getGuid());
	order.addReferences("Sales.Order_Tag", (Tags || []).map(t => t.getGuid()));
	return order;
	// END USER CODE
}
```

### Example B - "Validate on the server, then continue in the client"

Action: `Sales.JS_SubmitOrder(Order: Sales.Order, Validate: Microflow, AfterSubmit: Nanoflow) → Boolean`

```javascript
	// BEGIN USER CODE
	if (!Order) throw new Error("Order is required");
	const valid = await Validate({ Order: Order });          // microflow SUB_Order_Validate(Order) → Boolean
	if (!valid) return false;
	Order.set("Status", "Submitted");
	await AfterSubmit({ Order: Order });                     // nanoflow NF_Order_AfterSubmit(Order)
	return true;
	// END USER CODE
```

### Example C - "Sum a numeric attribute of any list" (type parameter, Big)

Type parameter `T`. Action: `Generic.JS_SumAttribute(Items: List(T), AttributeName: String) → Decimal`

```javascript
	// BEGIN USER CODE
	if (!AttributeName || AttributeName.trim() === "") throw new Error("AttributeName can not be empty");
	if (!Items || Items.length === 0) return new Big(0);
	if (!Items[0].isNumeric(AttributeName)) throw new Error(AttributeName + " is not numeric on " + Items[0].getEntity());
	return Items.reduce((sum, o) => sum.plus(o.get(AttributeName) || 0), new Big(0));
	// END USER CODE
```

### Example D - "Move tags from one order to another" (reference sets)

Action: `Sales.JS_MoveTags(From: Sales.Order, To: Sales.Order) → Integer`

```javascript
	// BEGIN USER CODE
	const guids = From.getReferences("Sales.Order_Tag");
	To.addReferences("Sales.Order_Tag", guids);
	From.removeReferences("Sales.Order_Tag", guids);
	return new Big(guids.length);                            // the nanoflow commits From and To
	// END USER CODE
```

## 8. Mistakes to avoid

| Mistake | Result | Do this instead |
|---|---|---|
| Code outside the BEGIN/END regions | Lost on next deploy | Imports at the top, helpers in EXTRA CODE |
| `order.set("Order_Customer", Customer)` | Error | Qualified name + GUID: `"Sales.Order_Customer", Customer.getGuid()` |
| Setting the association on the non-owner side | No change | Set it on the owner entity |
| `obj.set("Total", 12.5)` on a Decimal | Type error / precision loss | `new Big("12.5")` |
| Returning `undefined` for Boolean | Nanoflow error | Return `true` or `false` |
| Business logic in the action | Hard to reuse and test | Action does one thing; logic stays in the nanoflow |
| Calling a nanoflow by name | Not possible | Nanoflow parameter |
| `mx.data.action({ params: { actionname } })` to call a microflow | Legacy, not strict-mode safe | Microflow parameter (10.21+) |
| Client `create`/`commit` with strict mode on | Refused | Create/commit in the nanoflow, or call a microflow |
| Forgetting to commit | Changes are lost on reload | Commit activity after the call |
| Using DOM changes / Dojo / jQuery | Lost on re-render, deprecated | Use a pluggable widget for UI |
| Native-only library with platform All | Breaks on web | Set platform Native, or check support first |

## 9. Checklist before you finish

1. The action definition (parameters, return type, platform) matches the function signature and return value.
2. All code is inside the kept regions; extra imports are below the generated imports.
3. Associations use the qualified name and GUIDs, on the owner side.
4. Decimals use `Big`; Booleans are never `undefined`.
5. Nanoflow/microflow parameters are called with an object whose keys are the flow's parameter names.
6. The calling nanoflow commits created or changed objects.
7. Input is validated; errors are thrown with a clear message.
8. In Studio Pro: the Errors pane is empty and the nanoflow runs in the browser (check the console).
